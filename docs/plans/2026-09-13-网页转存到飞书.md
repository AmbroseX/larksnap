# 网页转存到飞书（剪存通道）

> 目标：侧边栏/右键把任意网页正文一次性转存为飞书云文档（用自有登录态，无需建开放平台应用）。
> 协议来源：对「飞书转存专家」v0.8.19 的逆向还原（见 `feishu-export/doc/02-feishu-api-and-clip-protocol.md`）。
> 状态：已实现并**端到端真机验证通过**（typecheck / vitest / build 全绿 + DNR 机制实测 + 真实登录态出一篇云文档）。

## 一、实现

### 协议客户端 `src/background/clip/feishu-clip.ts`

管线（对齐官方剪存协议）：

1. DNR 头伪装：把 `internal-api-space.(feishu.cn|larksuite.com)` 的 Origin/Referer 改成租户域
   （`withClipRefererRules`，规则 ID 33901/33902，独立段位、用完即删）
2. 小文件（≤30MB）：`POST /space/api/parser/wiki/parse_html/` multipart 直传 → ticket
3. 大文件：`box/upload/prepare/` → 批量 `box/stream/upload/merge_block/`（Adler32 校验，
   批失败逐块降级）→ `box/upload/finish/` → `parse_html`（fileToken）
4. 轮询 `/space/api/parser/wiki/clip/result?...&ticket=`（最多 100 次 × 1s）→ docUrl

关键常量：`clipVersion 1.0.40`、`X-Request-Source: feishu-clipper`、官方 cover icon
（见 `src/shared/constants.ts` 的 `CLIP_VERSION` / `CLIP_COVER_ICON` / `clipHostFor`）。

### 编排 `src/background/clip/clip-page.ts`

- ① 正文 HTML：复用剪藏注入管线（`webcopyClipHtml`；权限不足回 `needsPermission` 供同手势授权后重试）
- ② 租户解析：已授权租户 origin → 已打开的飞书文档标签 → 兜底 `my.feishu.cn`
- ③ 上传进度经统一进度通道推给侧边栏状态栏

### 接线

## 二、验证

### 静态验证
- `npm run typecheck`、`npx vitest run`（131 passed）、`npm run build` 全绿

### DNR 机制实测（CfT 迷你扩展）
- 枚举对象存在且取值正确（`MODIFY_HEADERS`/`SET`/`XMLHTTPREQUEST`），直接引用无需防御性降级
- **关键假设成立**：DNR `modifyHeaders` 作用于扩展 SW 自己发起的 fetch，可注入/改写 `Origin`/`Referer`
  （验证方式：CfT + `--load-extension` + 本地 HTTP 回显服务；SW fetch 不带 Origin 时规则照样注入成功）

### 端到端真机 E2E（2026-09-13 深夜）
- 环境：Chrome for Testing 150 + 本仓 `dist` + 从真实 Chrome 提取的 52 条飞书 Cookie（CDP
  `Network.getAllCookies` 明文读取后 `Storage.setCookies` 注入，绕开 macOS Keychain）+
  本地文章页（`/tmp/clip-e2e-test/article.html`）+ 真实租户（my.feishu.cn 登录态）
- 链路：options 页 → `chrome.runtime.sendMessage({type:'clip_to_feishu'})` → 正文提取 → parse_html
  直传 → 轮询 clip/result → **4 秒拿到 docUrl**
- 产物文档：真实存在于 session 归属租户（标题、多级标题、列表、代码块、来源链接均渲染
  正常；文档 URL 含真实租户标识，此处脱敏）
- 关键结论：**兜底 host（my.feishu.cn）上传的文档会落到 session 实际归属租户**，
  服务端按登录态归属，不依赖 host 猜测——比预想更宽容

## 三、降级与风险

- 剪存协议为非公开接口 + 伪装官方客户端标识（`X-Request-Source: feishu-clipper`）：存在风控风险
- 未登录判定：响应含 `未登录 / login required` 等关键字时直接报错（`LOGIN_RE`）
- 后续可接 CDP 粘贴（本仓库 editor 路线）作兜底通道
